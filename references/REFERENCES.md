# Reference Files Index

All reference files live in this directory. Agents load files using the absolute path to this folder.

**Maintenance:** user-shared materials are folded into these files via the `update-refs` skill ("update my references") — classification against this index, approval-gated writes, protected approved content. A new reference file may only be created after the usage interview in that skill, and must get a row in this index plus loading-table entries in every consuming agent before the add counts as complete.

| File | What it contains | Load when | Do NOT use for |
|---|---|---|---|
| `01-writing-rules.md` | **Configuration and rules.** Section 1: priority framework, attribution rules, fabrication guards, framing rules, JD term guardrails — read first. Section 2: operational identity (targets, differentiators, voice). Section 5: tone calibration and proof points. Section 8: contact details, education, tools, skills. **Setup required** — fill in all `{{...}}` placeholders before first run. | Every task — load first. Rules and constraints govern all other agents. | Approved bullets, summaries, testimonials, portfolio — those are in `02-professional-background.md`. |
| `02-professional-background.md` | **Career content bank + motivation bank.** Section 6: approved CV summaries by domain (grows with pipeline runs). Section 7: role facts and approved CV bullets per role — every claim must be grounded here. Section 9: testimonials. Section 10: portfolio and work samples. Section 5: motivation bank — standing answers plus durable content auto-promoted from Why I Want This Role (new-application Step 7f; edit Step E10.5). **Setup required** — fill in role facts before first run. | Every CV or cover letter writing task (role facts, bullets, summaries); every letter-writer run (motivation bank). | Rules and operational constraints — those are in `01-writing-rules.md`. |
| `03-framework.md` | **Positioning, voice, methodology, and domain narratives — the primary source of truth about the user.** Agents form their understanding of the user from this file first; single JDs, single applications, and LinkedIn data are situational context, never identity. Category frame, core positioning, value pillars, professional methodology (research-first, PLG, documentation, AI operating model), domain depth, ICP, messaging, taglines, differentiators, career-shift posture. | Cover letter writing, career coaching, strategic framing, LinkedIn recommendations (background guidance). | Rules, approved bullets, or raw facts. |
| `linkedin-profile.md` | **Snapshot of the user's current LinkedIn profile** (from their LinkedIn PDF export). The canonical base for every LinkedIn recommendation — orchestrator Step 8 and all linkedin-coach modes analyse against this content. Replaced wholesale via update-refs when the user exports a fresh PDF. **Optional** — when missing or still templated, LinkedIn outputs run in fallback mode (raw signals, no profile analysis). | Orchestrator Step 8 (LinkedIn updates file); every linkedin-coach mode that reads the profile. | The user's goals or positioning — that is `03-framework.md`. LinkedIn is a tool being improved, not a source of truth about the user. |
| `cv-self-check.md` | Mandatory pre-submission self-check for CV output. Covers ATS, summary, key achievements, experience, earlier line, header, and body word count. | Every CV draft and revision — run before returning any output. | Cover letters. |
| `job-preferences.md` | Full job search preferences — remote compatibility rules, target roles, seniority floor, industry fit, company stage, exclusion patterns, and coaching prioritization guidance. | Before any sourcing, scoring, or coaching step — load in career coach, coach skill, source-open-roles agent, and any agent that assesses remote fit or prioritizes roles. | Content writing or document production. |
| `{{CV_TEMPLATE_FILE}}` | CV reference template for pandoc conversion. Contains all custom styles and the document header. | Pandoc DOCX production only — loaded by `skills/career-engine-export/scripts/convert-cv.sh`. | Content decisions. |
| `cover-letter-template.dotx` | Cover letter reference template for pandoc conversion. | Pandoc DOCX production only — loaded by `skills/career-engine-export/scripts/convert-cv.sh`. | Content decisions. |
| `shared-voice-rules.md` | **Canonical cross-surface voice layer.** Aggregated from cv-writing, cover-letter, cover-letter-humanizer, and linkedin-coach skills. §1: punctuation prohibitions (em dashes, context-specific colons). §2: banned vocabulary (AI patterns, hollow filler, surface-specific bans). §3: banned phrases and constructions (named anti-patterns, opening/transition phrase bans, false dichotomies, oppositional rhetoric, vague phrases). §4: structural anti-patterns (antithesis/pivot, false range, approach-announcement, contrived tricolons, -ing appendages). §5: sentence mechanics (passive voice, subject-first, length variation, synonym cycling, filler phrases). §6: idiom prohibition. §7: positive writing standards. §8: LinkedIn post structure framework (engagement philosophy, Formats A/B/C, development process, quality checklist). Rules marked [CV], [CL], [LI] are surface-specific; unmarked rules apply everywhere. **WI1 aggregate — agents not yet pointed here; originals still carry local copies.** | Future: any agent writing professional content across surfaces. Now: reference for WI2 planning. | Personal data — that is `career-data`. Procedural steps — those are in agent files. |

Referred to elsewhere as "the Appendix-A handoff." | Setup skill (build-the-skill step), orchestrator and update-refs (Cowork update staging), any place that emits a `career-data` create/install/update handoff. | Personal data — never embed real values in this file; the agent fills the template at runtime outside the repo. |
