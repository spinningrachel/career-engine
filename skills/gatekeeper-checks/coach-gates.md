## Coach Output Check

For each role in the coach's output, identify every specific factual claim about the user's background, experience, skills, or accomplishments. Find the supporting line across the **full background set** — not the rules file alone:
- `01-writing-rules.md` — fabrication rule, framing rules, identity values
- `02-professional-background.md` — Role Facts, approved CV bullets, approved summaries, testimonials, portfolio (**this is where most proof actually lives** — named companies, metrics, outcomes, events, responsibilities)
- `03-framework.md` §Domain depth — per-vertical narratives (this is where domain/vertical credibility lives, e.g. defense, healthcare, developer audiences)

A claim is verifiable if it traces to **any** of these three files. Checking against `01` alone produces false positives on real, documented claims (a defense event documented in `02`, a vertical narrative in `03` §Domain depth) — that is a check failure, not a fabrication. Read `02` and `03` §Domain depth before flagging anything as unverifiable.

**Verifiable:** directly traceable to a named section, sentence, or bullet in `01-writing-rules.md`, `02-professional-background.md`, or `03-framework.md` §Domain depth.

**Unverifiable:**
- Names a company, client, product, or tool the user worked with that does not appear in **any** of the three background files
- Attributes a metric, outcome, or responsibility not found in **any** of the three background files
- Describes a skill or domain depth that is not documented in `02` Role Facts or `03` §Domain depth

**Do not flag (for the fabrication check):**
- Claims about the role or company (from the JD, not the user's background)
- Role emphasis sentences describing what the role requires
- Letter Outline subjects — directional guidance, not new factual claims (any capability they reference must still trace to `02`/`03`, which the fabrication check above covers)
- Gap handling entries identifying what the user does NOT have (gaps are expected absences, not fabrications)

### Field-fit and format checks

The fabrication check above verifies *traceability*. It does NOT catch content that is true but **in the wrong field**, **over a length cap**, or that **leaks a disabled feature** — the recurring coach defects. Run these in addition; **any hit is a FAIL** that returns to the coach for revision, exactly like a fabrication FAIL. (These examine field placement and format; they do not re-judge the framing the fabrication check already exempts.)

1. **Role summary contamination — JD-only.** FAIL if `Role summary` references the candidate ("she/her", her name), her fit, her seniority or title, a title she "hasn't held," a gap, or "transferable." `Role summary` describes the job only. Quote the offending sentence.
2. **Culture contamination — working-style only, no Landscape data.** FAIL if `Culture` contains specific financial or structural FACTS: dollar/revenue/funding figures, EBITDA numbers, named acquisitions or prices, exchange tickers (NYSE/NASDAQ), founding year, employee headcount, or segment names. Those belong in `Landscape`. A qualitative culture framing that references a posture ("profitability-first culture") is fine; the financial *data* is not.
3. **Gap leak when gap handling is disabled.** ONLY when the spawner states gap handling is disabled for this run: FAIL if any coach property OR the Letter Outline enumerates gaps — "gap", "the X real gaps", "doesn't have / lacks / missing", or any catalog of what the candidate lacks. A disabled feature must suppress the behavior everywhere (affirmative transfer claims in the Letter Outline only, never a gap inventory).
4. **(Retired 2026-07-23 — was the coach-context-block transfer-note length cap; the block itself is retired. Number kept so later checks don't renumber.)**
5. **Outreach self-contact / advice.** FAIL if the outreach map contains, anywhere, the user's own email, phone, or contact line, or any drafting/application advice ("lead with…", "available now"). The map is a hiring-side contact table only.
6. **Length caps and `Role emphasis` structure.** FAIL if `Keywords` exceeds 9 total (Critical >4, Important >3, or Nice-to-have >2); or `Culture` exceeds 3 bullets; or `Role emphasis` deviates from its fixed two-line structure (2026-07-24, per the user: "Emphasis: / Likely KPIs: / And that's it"): exactly **Emphasis** / **Likely KPIs**, nothing else, **≤100 words total (count mechanically — wc -w via Bash, never an estimate)**. Also FAIL if `Role emphasis` contains any of the banned content classes: a `De-emphasized`/non-emphasis line, any capability mapping or candidate reference ("maps to her...", any mention of the user — both retired 2026-07-24 per the user's direct instruction), strategy/letter-strategy content, a CV Type recommendation, company facts beyond a one-clause operating-model translation of an ambiguous term, a `[HIGH]`/`[LOW]` confidence tag, or step-up/step-down/rank/seniority commentary — each of these is a confirmed live defect this check exists to block.
7. **Mandatory-field presence.** For every role in the coach's output that completed full research (not a triage exit, Priority 1–4), FAIL if any of the following has no value at all — not even `Unknown`/`[LOW]`/`N/A` where the property's own rules permit that as a valid value: `Role summary`, `Priority`, `Priority Reason`, `Role emphasis`, `Keywords`, `Strategy`, `Role Type`, `Relationship type`, `Culture`, `Landscape`, `JD proof`, `Company Stage`, `Hiring manager's role`, `Manager role confirmed`, `No incumbents in this function`, `Gap handling` (skip this one check if the spawner states gap handling is disabled for this run), `Location` (skip this one check if the spawner states the database has no `Location` property; a `Location` of `Unknown` additionally requires a `## Location Hypotheses` section in `Landscape` — FAIL if absent), `JD Body` (skip this one check for a role marked `content-exists` or `needs-manual` in Step 0.5 — only check it for a role marked with any `url-fetched*` marker this run), `Date first advertised`/`First Advertised`, `CV Type` (ONLY when the spawner states `cv_type_mode` is `Variant`; skip otherwise), and the **`letter_plan`** block (also covered structurally by check 12). **Also FAIL if `Hiring manager's role` and `Manager role confirmed` are merged into a single field under any other name (e.g. a free-text "Hiring Manager" field combining name, title, and confirmation status)** — a real production run did exactly this, dropping both named properties while appearing to answer the question. This list must stay in parity with the Step 0.8 coach-complete list and the Step 0.9a confirmation-pass list in `skills/career-engine-intake/SKILL.md` — see the Cross-file contracts table in `CLAUDE.md`. Name every missing field by role; this is a structural presence check independent of the fabrication and field-fit checks above, which cannot catch an omitted field. (The location-compatibility result and the `Why I Want This Role` coach context block were removed from this list 2026-07-23 — both features retired per the user's direct instruction.)
8. **Outreach map structural purity.** The outreach map is the ONLY page-body content in the entire intake pipeline, and it must have identical structure every run. FAIL if the coach's `**Outreach map:**` return, for any role, contains anything beyond exactly these TWO parts (2026-07-23 — Note angles and Email/WhatsApp retired per the user's direct instruction): the `## Outreach — <Company>` heading, the ≤3-row table. In particular, FAIL on a `**Note angles**` section, an `**Email / WhatsApp**` section, a "Writing Angle" section, a "Message angle" section, numbered interview-style questions embedded in or adjacent to the map, or any other free-text commentary that isn't one of the two named parts. Quote the offending content and name the role. This check runs before intake ever writes to Notion (Step 0.8.5, ahead of the Step 0.9e page-body write) — it is the first line of defense; Step 0.9e's own extraction rule is the second.
9. **Search-narrative leakage (2026-07-23 — replaces the retired coach-context-block check).** FAIL if any property value carries the story of the research instead of the result: a negative reported as anything longer than the bare value (`Not identifiable`, `Unknown`, `None found`), bracketed process notes ("[checked LinkedIn, Glassdoor, theorg — nothing]"), "despite checking X and Y" clauses, or a `[HIGH]`/`[LOW]` tag in a property whose format does not define one (`Role emphasis` in particular defines none). The Research confidence check block is the only sanctioned place for attempt enumeration. FAIL also if a retired output shape appears anywhere: a `**Coach context**` / Screen-points block, or a `[COACH PROMPTS]` questions block — both retired 2026-07-23. Quote the offending text and name the role.
10. **JD Body content type — verbatim JD text only (2026-07-16).** FAIL if the coach's `JD Body` value is anything other than the job posting's own text: any first-person candidate material ("I run GTM as...", "I have deep experience..."), any quote from the user's career-data or Motivation Bank, any JD-section-to-background mapping, any synthesized dossier or analysis. **Confirmed production failure this closes:** a real run's coach filled `JD Body` for a VP Marketing role with a multi-section anthology of the user's own quotes mapped to the JD's headings — hours of unsanctioned work, personal material duplicated into the tracker, and the actual JD text never cached. `JD Body` is a verbatim-text cache the pipeline's own fetch supplies; the coach passes fetched JD text through untouched or returns nothing for it. Quote the first offending line and name the role.
11. **No unsanctioned deliverables anywhere.** FAIL if any property value contains a deliverable the coach was never asked to produce — a quote anthology, a letter-material dossier, a prep document, an interview guide, or any content whose format is not defined in `coach-output.md` for that property. The coach's job ends at the sanctioned outputs; if it believes extra analysis would help, it says so in ONE Patterns line, it does not produce the analysis. Same real incident as check 10.
12. **Letter Outline presence and format (2026-07-22; markers renamed 2026-07-23; `Opener anchor` retired 2026-07-24, per the user's direct instruction: "Get rid of the hook. the opener anchor. that's what's causing this mess.").** For every full-research role (Priority 1–4), FAIL if the coach's `letter_plan` return is missing, or does not contain all three parts between its `[LETTER OUTLINE` ... `[/LETTER OUTLINE]` markers: a `Template:` line, an `Opener:` line (added 2026-07-24), and at least two `Para N:` outline lines. **FAIL if the block contains an `Opener anchor:` line — the anchor is retired; its slot was the confirmed injection vector for composed research prose (the Reflectiz "$22M... and I want to be the first marketing executive who..." incident), and no coach-authored hook line of any name may reappear.** FAIL if a NEW output uses the legacy `[COACH LETTER PLAN` markers (consumers still read the legacy form on old rows; the coach must never write it again). FAIL if any outline line describes HOW to write rather than what the paragraph is about. **FAIL — Template line not the bare token:** anything on the `Template:` line beyond the template identifier (a rationale clause, a dash-explanation) — that value is copied verbatim into `$PIPE/template-selection.txt`, specced as a single token. **FAIL — `Opener:` line not a verbatim bank copy (2026-07-24, per the user's direct instruction):** read the selected template's Block 1 Variants (the user's `${CAREER_DATA}/references/templates/cover_letter_templates.md`; the plugin's `references/cover-letter-templates-default.md` only when the user's file is absent) and diff — the `Opener:` value must be one variant reproduced verbatim with ONLY `{ROLE}`/`{COMPANY}` substituted; FAIL if it is a composed sentence matching no variant, blends variants, fills any other placeholder (`{SELF_LABEL}`, `{IDENTITY_IDIOM}`, proof slots...), or omits the `(variant <n>)` attribution. Triage-exit roles (Priority 5–6) are exempt.

Each FAIL names the property, quotes the offending text (or states "missing entirely" for check 7), and states the fix.
